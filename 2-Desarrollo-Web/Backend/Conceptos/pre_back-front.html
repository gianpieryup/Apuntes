Arquitecturas de Comunicación

(Cliente - Servidor)

REST API, Short Polling, Long Polling, WebSockets y SSE

Usa las flechas del teclado para navegar

1. REST API

🍔 Analogía: Pedir comida rápida. Pides, te dan la comida y te vas. Si quieres más, tienes que volver a formarte y hacer la fila de nuevo.
sequenceDiagram participant C as Cliente participant S as Servidor C->>S: Petición (¡Quiero una hamburguesa!) Note over S: Prepara la orden S-->>C: Respuesta (Aquí tienes)

2. Short Polling

🚗 Analogía: El niño en el auto preguntando "¿Ya llegamos?" cada 10 segundos. El padre responde "No" muchas veces hasta que al final dice "Sí". Mucho esfuerzo desperdiciado.
sequenceDiagram participant C as Cliente participant S as Servidor C->>S: Petición: ¿Hay datos? (t=0s) S-->>C: Respuesta: No. C->>S: Petición: ¿Hay datos? (t=10s) S-->>C: Respuesta: No. C->>S: Petición: ¿Hay datos? (t=20s) S-->>C: Respuesta: ¡Sí, toma los datos!

3. Long Polling

🤫 Analogía: El niño pregunta "¿Ya llegamos?" y el padre se queda en completo silencio por horas. Solo habla cuando finalmente llegan y dice "Sí". Inmediatamente, el niño vuelve a preguntar.
sequenceDiagram participant C as Cliente participant S as Servidor C->>S: Petición HTTP (¿Hay datos?) Note over S: Servidor espera en silencio... Note over S: ¡Aparecen nuevos datos! S-->>C: Respuesta con los datos C->>S: Inicia nueva petición inmediata Note over S: Servidor vuelve a esperar...

4. WebSockets

📞 Analogía: Una llamada telefónica bidireccional. Ambos están conectados en línea abierta y pueden hablar o interrumpirse en cualquier momento.
sequenceDiagram participant C as Cliente participant S as Servidor C->>S: Handshake (Inicia Llamada) S-->>C: Conectado Note over C,S: Conexión abierta bidireccional S->>C: "Hola, te mando datos en vivo" C->>S: "Recibido, yo te mando mis acciones" S->>C: "Otra actualización instantánea"

5. Server-Sent Events (SSE)

📻 Analogía: Escuchar la radio. Sintonizas la estación (te conectas) y solo te dedicas a escuchar lo que el locutor (servidor) transmite.
sequenceDiagram participant C as Cliente participant S as Servidor C->>S: Conectar (Sintonizar estación) S-->>C: Conectado Note over S: Servidor transmitiendo... S->>C: Evento (Noticia 1) S->>C: Evento (Canción 2) S->>C: Evento (Alerta 3)
